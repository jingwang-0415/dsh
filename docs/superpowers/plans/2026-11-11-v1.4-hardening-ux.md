**Files:**

- Test: `server/test/refDiff.test.ts`、`server/test/gitRunner.test.ts`、`server/test/api.test.ts`、`server/test/sse.test.ts`（追加）

**Interfaces:**
- Produces:
  - `classifyChange`：仅 `GitCommandError.exitCode === 1` → force-push；**spawn 失败（ENOENT）、超时（timedOut plain Error）、其他非零退出（如 128 对象缺失属"镜像缺对象"仍算 force-push？——裁定：** exitCode===1 与 exitCode===128 且 stderr 含路径语义均按现状 force-push（镜像缺对象是常见瞬态，语义等价），**仅 spawn error/timeout 归为失败重抛**（调用方 scheduler 按失败轮处理）。实现：区分 `err instanceof GitCommandError`（→ 按退出码判定）与 `err instanceof Error && 非 GitCommandError`（→ rethrow）
  - runGit：`child.stdin?.destroy()` 加到超时路径（与 stdout/stderr 对称）
  - GitCommandError 消息凭证脱敏：`sanitize(s)` 将 `(https?|ssh):\/\/[^@\s/]+@` 替换为 `***@`（凭据段）；应用于 message 拼装（args 与 stderr 均 sanitize）；GitResult/GitCommandError.stderr 字段保持原样（调用方无 UI 直出 stderr——fetch_events 存的是 error message ✓ 已脱敏）
  - `/api/commits` limit clamp：`Math.min(Math.max(limit,1),500)`（上限 500；offset ≥0 不变）——超出部分静默钳制（400 语义留给负数/非整数）
  - sse.ts：publish 摘除与 ping sweep 摘除后调用 `stopHeartbeatIfIdle()`（两行）
