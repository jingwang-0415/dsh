### Task 3: 大仓化——指纹管道流式 + showCommits 分批

**Files:**
- Modify: `server/src/gitRunner.ts`、`server/src/patchid.ts`、`server/src/crossrepo.ts`
- Test: `server/test/gitRunner.test.ts`（追加 pipeRunGit 用例）、`server/test/patchid.test.ts`（既有用例改为等价性断言）

**Interfaces:**
- Produces:
  - `pipeRunGit(cwdA: string, argsA: string[], cwdB: string, argsB: string[], opts?: { timeoutMs?: number }): Promise<GitResult>`——A.stdout 直连 B.stdin（双 spawn），收集 B stdout Buffer 拼接；A.stderr/B.stderr 捕获；任一进程失败/超时（默认 120s，双进程同超时 kill）→ reject（GitCommandError 语义，args 标注两段）；A 正常结束而 B 未结束属正常流关闭
  - `branchFingerprints` 内部改用 pipeRunGit（删除整段 patchText 驻留）；外部签名/返回不变
  - `showCommits(mirrorDir, shas)`：按 `SHOW_BATCH = 200` 分批循环调用，结果顺序拼接

- [ ] **Step 1: 写失败测试**——gitRunner.test.ts 追加：`pipeRunGit(dir, ['rev-list','--max-count=5','--pretty=format:%H','--no-merges','HEAD'], dir, ['patch-id','--stable'])` 返回行数 ≤5 且末列 sha ∈ HEAD 历史（真实 fixture）；patchid.test 追加等价性用例：构造多提交分支，`branchFingerprints` 结果与 v1.1 实现的期望值逐条相等（回归锁——流式改造前后结果一致）
- [ ] **Step 2: RED 确认**（pipeRunGit 不存在）
- [ ] **Step 3: 实现 pipeRunGit**——spawn A（stdout pipe）、spawn B（stdin pipe/stdout pipe/stderr pipe）；`a.stdout.pipe(b.stdin)`；A 'close' 后 `b.stdin.end()`；stderr 各自累加；timer 超时双 kill（timedOut 语义同 runGit）；A 非 0 → reject GitCommandError(argsA, code, stderrA)；B 非 0 → reject GitCommandError(argsB, code, stderrB)；B close → resolve Buffer.concat(stdoutB)。error handler 双方注册
- [ ] **Step 4: branchFingerprints 切换 + showCommits 分批**——`const { stdout: idText } = await pipeRunGit(mirrorDir, logArgs, mirrorDir, ['patch-id','--stable'])`；showCommits 循环 `for (let i=0;i<shas.length;i+=200)` 收集
- [ ] **Step 5: 全绿 + 提交** `git add server/src server/test && git commit -m "perf: patch-id 管道流式与 showCommits 分批（大仓化）"`
