### Task 1: 后端 gitConfigPath 传输兜底

**Files:**
- Modify: `server/src/mirror.ts`、`server/src/config.ts`、`server/src/scheduler.ts`、`server/src/api.ts`
- Test: `server/test/mirror.test.ts`（追加）、`server/test/config.test.ts`（互斥 refine）、`server/test/reposapi.test.ts`（往返）

**Interfaces:**
- Produces:
  - `TransportOpts` 增 `gitConfigPath?: string`——env 分支三分：bypass → GLOBAL/SYSTEM 均 /dev/null；gitConfigPath → `GIT_CONFIG_GLOBAL=<path>`（SYSTEM 保留机器级）；均未设 → 无 env 键。互斥在 config 校验层挡（refine），mirror 层 defensive：bypass 优先
  - repoSchema 增 `gitConfigPath: z.string().optional()` + refine `!(bypassGitConfig && gitConfigPath)`（消息"bypassGitConfig 与 gitConfigPath 互斥"）
  - POST/PATCH：gitConfigPath 键白名单；提供时 `existsSync` 校验 → 400 git_config_not_found（创建时点校验；运行中被删由 git 报错如实呈现）；GET/POST/PATCH 行含字段（undefined 省键）
  - PATCH 三态联动：网络连接方式下拉与 gitConfigPath 正交（跟随系统模式下也可指定配置文件——注意前端需在 system/none/custom 三态下都透传 gitConfigPath）
  - 前端 web 传输区（Task 2 契约）：新增"自定义 git 配置文件（可选）"输入框 + 与直连 checkbox 互斥提示

- [ ] **Step 1: 写失败测试**
  - mirror.test：`transportOptsEnv({bypassGitConfig:true})` → 双 /dev/null；`transportOptsEnv({gitConfigPath:'/x/cfg'})` → 仅 GIT_CONFIG_GLOBAL=<path>；均未设 → 无 env 键（extract `transportOptsEnv` 纯函数便于断言——env 构造从 mirror 内联抽纯函数）
  - config.test：双设 → throws 含"互斥"
  - reposapi.test：POST 带 gitConfigPath（先 touch 真实临时文件）→ 201 → GET 回显；POST 不存在路径 → 400 git_config_not_found；PATCH 更新路径 → 回显；PATCH bypass+path 双设 → 400 互斥

- [ ] **Step 3: 实现**（mirror env 三分支抽纯函数；config schema+refine；api 白名单/校验/映射；scheduler 透传）
- [ ] **Step 4: 全绿**（server 138 + 新增 ≈5-6 = 143-144）
